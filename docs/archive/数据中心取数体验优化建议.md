# 数据中心 · 数据查询取数体验优化建议

| 项 | 内容 |
|---|---|
| 版本 | **v1.1（含评审记录）** |
| 作者 | 高级产品经理 |
| 日期 | 2026-07-28 |
| 涉及模块 | `data_callbacks.py`（回调） / `data_center.py`（布局） |

---

## 1. 现状问题

当前「数据查询」Tab 的取数功能（点击"开始获取数据"）已支持日线/分钟线/复权因子/财务数据四种数据类型，但存在以下体验问题：

| 编号 | 问题 | 用户感知 | 优先级 |
|---|---|---|---|
| Q1 | **分钟线日期范围不友好**：切换到分钟线时，日期范围默认仍是日线的"2024-01-01 ~ 2024-12-31"，一次拉取一年的分钟数据量极大，效率低且无意义 | **P0** |
| Q2 | **取数过程无进度**：同步取数，多个标的时前端无反馈，用户不知道拉了多少个 | **P1** |
| Q3 | **取数后无跳转入口**：数据拉取完成后，用户需要手动切换到"已缓存数据"或"行情看板"查看，路径断裂 | **P1** |
| Q4 | **分钟周期选择默认值不够合理**：默认 5 分钟，但用户常用场景也包括 1 分钟高频、60 分钟日级别跨度 | **P2** |
| Q5 | **取数上限无提示**：MAX_FETCH_SYMBOLS=20 但用户看不到上限，选多了静默截断 | **P2** |

---

## 2. 优化建议

### Q1 分钟线自动调整日期范围（P0）

**当前行为**：切换到分钟线时，日期范围保持为日线的默认值 `2024-01-01 ~ 2024-12-31`。

**建议**：
- 新增回调 `on_data_type_change`：监听 `data-type-radio.value` 变化。
- 当用户选择"分钟线"时，自动将 `date-range-picker` 的 `start_date` 设置为 7 天前（`datetime.now() - timedelta(days=7)`），`end_date` 设置为今天。
- 当用户切回"日线"时，恢复默认的当年范围（或保留用户手动设置的值）。
- 用户手动修改日期范围后，不受自动切换影响（通过 `prevent_initial_call` 和 State 对比）。

**交互**：
- 选择"分钟线" → 日期范围自动缩至近 7 天
- 选择"日线/复权/财务" → 日期范围恢复默认
- 用户手动调过日期后，自动切换不再覆盖（通过 State 记录用户是否手动修改过）

### Q2 取数进度实时反馈（P1）

**当前行为**：`fetch_data` 同步拉取所有标的，完成后一次性输出结果。期间按钮显示"获取中..."，无中间进度。

**建议**：
- `fetch_data` 改为逐标的单次输出模式，或利用 `running` 配置增强中间状态。
- 更务实的方案：在 `fetch_data` 执行过程中，每次成功/失败一个标的，即时追加一行到 `fetch-results`（利用 `dcc.Interval` 轮询进度 store）。
- 简化方案：新增 `dcc.Store(id="fetch-progress-store")`，`fetch_data` 每完成一个标的就更新该 Store；新增回调监听该 Store → 实时追加结果显示。

### Q3 取数后提供跳转链接（P1）

**当前行为**：取数完成后结果显示在 `fetch-results` 中，但用户需手动切到其他 Tab 查看。

**建议**：
- 在 `fetch-results` 底部追加操作入口：
  - `[查看已缓存数据 →]` 跳转到 `?tab=tab-cached` 并定位到该标的
  - `[去行情看板 →]` 跳转到 `/market-watch?focus=<获取的标的>`
- 跳转方式：`dcc.Link` 或 callback 设置 `url`。

### Q4 分钟周期默认值优化（P2）

**当前行为**：分钟周期 Dropdown 默认 `5min`。

**建议**：
- 默认改为 `1min`（1 分钟线，最细粒度，用户可自行切到更粗周期）。
- 添加提示文字："建议近 7 天 1 分钟线数据量约 XXX 条"（根据已选标的数动态计算）。

### Q5 取数上限可视化（P2）

**当前行为**：`MAX_FETCH_SYMBOLS=20` 静默截断。

**建议**：
- 在"开始获取数据"按钮下方常驻提示"可同时获取最多 20 个标的"。
- 当已选标的 ≥ 15 时，提示"已选 N 个标的，接近上限 20"。
- 当超过 20 个时，按钮文本变为"获取前 20 个标的（共 N 个）"。

## 3. 功能需求（FR）

### FR-Q1 分钟线智能日期

- 新增回调 `on_data_type_change`：Input `data-type-radio.value`，Output `date-range-picker.start_date`/`end_date`。
- 分钟线：`start_date=(today - 7d).isoformat()`, `end_date=today.isoformat()`。
- 日线：`start_date="2024-01-01"`, `end_date="2024-12-31"`。
- 用户手动修改后停止自动覆盖（通过 State 记录用户是否曾手动修改过）。

### FR-Q3 取数后跳转

- `fetch_data` 回调新增 Output `fetch-results` 底部追加操作链接。
- 链接格式：`[📋 查看已缓存数据](?tab=tab-cached)` + `[📈 去行情看板](/market-watch?focus=<ticker>)`。

### FR-Q5 上限提示

- 新增回调或合并到 `guard_fetch_button`：在 `fetch-guard-hint` 中追加上限提示。
- 当已选池 ≥ 15 时显示"已选 N 个标的"。
- 按钮文本可根据池数量动态调整。

## 5. 产品决策

1. **Q1 自动日期不追踪用户手动设置（评审 D2）**：PRD 初稿说 State 追踪"用户是否手动修改过"，但 `dcc.DatePickerRange` 的 `start_date`/`end_date` 属性无法区分是用户输入还是回调写入。简化方案：每次切数据类型都重设日期，用户如果觉得日期不对随时可以手动调整。这是最简洁可靠的方案。
2. **Q3 跳转只加链接不做自动跳转**：不自动导航页面，避免打断用户查看取数结果。只提供操作入口由用户点击。
3. **Q2 进度方案选简化版**：当前同步取数模式对 <= 20 个标的够用，不做复杂进度改造。后续如需支持大容量取数再重构为后台回调+进度轮询。
4. **Q4 1 分钟为默认**：1 分钟是最细粒度，用户可切到更粗周期。

## 6. 评审记录（开发 / 设计 / 测试）

> 评审日期 2026-07-28。基于代码走查（`data_callbacks.py` `fetch_data` / `guard_fetch_button` / `toggle_minute_period`，`data_center.py` 组件）。

### 开发视角

| 编号 | 发现 | 严重度 | 修订动作 |
|---|---|---|---|
| D1 | **`guard_fetch_button` 不能输出 `fetch-data-button.children`** | **高** | `fetch_data` 的 `running` 配置（L264-265）已注册 `Output("fetch-data-button", "children")` 为 "获取中..." / "开始获取数据"。若 `guard_fetch_button` 也输出同一属性，Dash 报 DuplicateCallback 错误。**方案**：Q5 上限提醒只加到 `fetch-guard-hint`，不改按钮文本。已更新 §4。 |
| D2 | **State 追踪"用户手动修改"不可行** | 中 | `dcc.DatePickerRange` 的 `start_date`/`end_date` 输出不具备区分手动/自动的能力。每次切类型自动设日期，用户不满意可自行再调。已更新 §5 决策 1 和 §4。 |
| D3 | **跳转链接组件选择** | 低 | `fetch-results` 是 `html.Div`，组件树内。跳转链接可用 `dbc.Button(href="/market-watch?...")` 或 `dcc.Link`。建议用 `html.A` markdown 式简洁链接，复用 `fetch-results` 的 `html.P` 行结构。 |

### 设计视角

| 编号 | 发现 | 严重度 | 建议 |
|---|---|---|---|
| DES-1 | **跳转链接位置**：当前 fetch-results 末尾追加链接，但如果取数结果很多，用户需滚动到底部才能看到。建议在结果摘要行（`summary`）旁直接放链接，更醒目。 | 低 | `fetch-data` 的 `summary` 改为 `html.Div([summary_text, links])`，与结果列表同层。 |

| 编号 | 发现 | 严重度 | 动作 |
|---|---|---|---|
