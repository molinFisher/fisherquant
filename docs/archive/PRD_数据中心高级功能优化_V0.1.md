# 数据中心 · 高级功能优化建议（PRD 草案 v0.1）

> 视角：高级产品经理
> 范围：数据中心页（数据查询 / 已缓存数据 / 高级功能 / 自动加载）
> 依据：基于代码实测梳理的现状，而非空想。括号内标注对应代码位置。

---

## 0. 现状盘点（实测结论）

| 模块 | 现状 | 问题 |
|---|---|---|
| 自动加载-时间范围 | 日线起点硬编码 `AUTO_LOAD_CFG.initial_start = "2024-01-01"`，分钟滚动窗口默认 60 天（`prune_minute_window`） | 用户无法调，冷门长周期研究受限；分钟窗口也不透明 |
| 自动加载-数据类型 | 固定组合：日线全量 + 日线补缺 + 分钟滚动 + 实时快照；**不含复权因子/财务数据**（仅手动取数才有） | 无法按需开关，全量加载耗时长、占空间、易触发限流 |
| 自动加载-宇宙 | `cache_catalog.auto_load_enabled=TRUE` 的标的；该字段由"加入看板"副作用写入（`data_cache_callbacks.py:289`、`quote_callbacks.py:526`） | 无独立可见开关，用户不知道谁在自动加载、如何退出 |
| 高级功能·自动刷新 | Tab 内有 `auto-refresh-toggle` / `auto-refresh-cron` / `next-refresh-time`，但**全项目无任何回调接线** | 死功能，误导用户，应修复或下线 |
| 高级功能·数据导出 | 导出 `get_cached_table()` 的**缓存目录汇总表**（ticker/名称/覆盖起止/行数），日期筛选作用在覆盖区间列 | 用户以为导出的是行情，实际是"清单"；无法导出真实 OHLCV |
| 高级功能·复权因子 | 单标的查询 `bars_daily.adj_factor`，展示前 20 行 | 无批量、无区间、无导出、无可复制 |
| 数据查询 | 手动取数（日期范围 + 数据类型 + 分钟周期 + 保守模式），"当日"按钮已加；默认范围终点已改为当日（2024-01-01 ~ today） | 取数后无"加入自动加载"入口，与自动加载割裂；「当日」按钮三方评审见 `PRD_时间范围当日按钮_V1.0.md` |

**一句话结论**：数据中心的"自动加载"和"高级功能"骨架已立，但**缺少用户侧的可配置性与可达性**，且存在 1 个死功能（自动刷新）、1 个名不副实功能（导出）。本次优化聚焦两件事：① 让自动加载可配置（时间范围 + 数据类型）；② 把其余功能做"有意义"——修复/增强而非堆砌。

---

## 1. 需求一：自动加载的时间范围 & 数据类型设置

### 1.1 目标
让用户对"哪些标的、下什么、下多久"拥有**明确、可持久化、可回看**的控制权，在"省时间/省空间/降限流"与"数据完整度"之间自主权衡。

### 1.2 功能需求（FR）

**FR-A1 · 自动加载设置面板**（新增，建议在「自动加载」Tab 顶部或独立「自动加载设置」卡片）
- FR-A1.1 提供全局设置项：
  - **日线时间范围**（RadioItems + 自定义日期）：
    - 全历史 / 近 3 年 / 近 1 年 / 近 6 个月 / 自定义起止
    - 语义：仅影响"首次全量下载（FULL 计划）"的起始日；已缓存数据不受影响（补缺 GAP 逻辑不变）。
  - **分钟线滚动窗口**（数字输入，单位天，默认 60）：
    - 控制 `prune_minute_window` 的 `window_days`，窗口外旧分钟线惰性清理。
  - **数据类型开关**（Checkbox，多选）：日线 / 分钟线 / 实时快照 / 复权因子 / 财务数据
    - 默认勾选：日线、分钟线、实时快照；复权因子、财务数据默认不勾（按需，避免拉全市场财务拖垮加载）。
- FR-A1.2 设置**持久化**：写入 `auto_load_status` KV（或新增 `auto_load_settings` 表），启动时由 `AUTO_LOAD_CFG` 之外的 `load_settings()` 合并覆盖，UI 打开时回填。
- FR-A1.3 设置变更**不立即删除已有数据**；仅影响"下次自动加载计划"。变更后给出"将应用于下一次加载/重新规划"的弱提示。
- FR-A1.4 提供「应用并重新规划」按钮 → 触发轻量 `replan()`（复用现有 `reload(force_full=False)` 的计划逻辑），把新时间范围/数据类型纳入账本，不清历史行情。

**FR-A2 · 时间范围与数据类型的消费**（服务层改造）
- FR-A2.1 `build_plan()`：日线 FULL 计划的起点改用设置中的日线起始日，而非 `AUTO_LOAD_CFG.initial_start`。
- FR-A2.2 `run()` / 增量更新：按数据类型开关跳过未选类型（如未勾"分钟线"则跳过 `_download_minute`；勾选"复权因子/财务数据"则新增对应下载分支）。
- FR-A2.3 复权因子/财务数据作为自动加载的新增可选类型，复用已实现的手动取数函数，确保 `record_coverage` 显式传 `name`（呼应已修复的 A 股名称问题）。

**FR-A3 · 与现有 `auto_load_enabled` 协同**
- FR-A3.1 设置是"全局规则"，`auto_load_enabled` 是"标的白名单"，两者 AND：仅白名单内、且数据类型被选中的标的/类型才会被加载。
- FR-A3.2 在「已缓存数据」Tab 暴露每行的"自动加载"开关（当前无），让可达性闭环。

### 1.3 设计要点（D）
- D-1（防误删）：时间范围调小**不触发删数**，仅影响未来下载起点；如需回缩历史，走明确二次确认的"截断历史"操作（不在本次范围，列作后续）。
- D-2（持久化选型）：放 DB KV 而非 `configs/system.yaml`（静态、需重启），保证 UI 改完即时生效、跨重启保留。
- D-3（限流友好）：默认数据类型精简、窗口收敛，天然降低请求量，与现有 `RateLimiter` 协同。

### 1.4 验收（AC）
- AC-1：修改日线时间范围为"近 1 年"并重新规划后，新标的一次性下载起点为约 1 年前，非 2024-01-01。
- AC-2：取消"分钟线"勾选后，自动加载仅下日线+实时，分钟增量更新跳过。
- AC-3：勾选"复权因子"后，自动加载宇宙内标的补下复权因子并写入 `adj_factors`。
- AC-4：设置写入后重启服务，UI 重新打开仍为上次值（持久化生效）。
- AC-5：修改设置不删除任何已缓存行情数据。

## 2. 需求二：其他高级功能梳理与增强

### 2.1 自动刷新（高级功能 Tab）—— 修复死功能，否则下线
- 现状：UI 控件完全无回调，是"假功能"，损害专业性。
- 增强方案（FR-A4）：
  - 实现 `auto-refresh-toggle` + `auto-refresh-cron` → 真正调度"盘后增量更新"（`incremental_update` / `incremental_update_minute`）。
  - `next-refresh-time` 根据 cron 实时计算展示下次触发时刻（用户心里有底）。
  - 若工期紧：**直接下线该卡片**，避免误导（宁缺毋滥）。
- 优先级：**P0**（信任问题）。

### 2.2 数据导出 —— 让导出"名副其实"
- 现状：导出的是缓存目录汇总表，非行情；日期筛选作用在覆盖区间。
- 增强方案（FR-A5）：
  - 导出对象改为**真实行情**：根据筛选标的 + 数据类型（日线/分钟）+ 起止交易日，`JOIN bars_daily / bars_minute` 导出真实 OHLCV/成交量。
  - 日期筛选作用在 `trade_date`/`bar_time`（而非覆盖区间列），语义正确。
  - 增加"数据类型"选择（日线/分钟），分钟支持周期（1/5/15/30/60min）。
  - 大结果分文件或提示行数上限，避免内存爆炸。
- 取舍：保留"导出覆盖清单"作为子选项（研究管理用），但**默认导出真实行情**。
- 优先级：**P0**（功能名实不符，最伤体验）。

### 2.3 复权因子查询 —— 从"玩具"到"好用"
- 现状：单标的、前 20 行、不可复制/导出。
- 增强方案（FR-A6）：
  - 支持逗号分隔**批量标的**（如 `600519.SH,000001.SZ`），横向对比复权起点/末值。
  - 支持**时间区间**过滤；结果可一键**复制为 CSV / 导出**（与 FR-A5 复用导出通道）。
  - 增加"前复权/后复权/不复权"口径说明（当前 `adj_factor` 口径需标注）。
- 优先级：**P2**（锦上添花）。

### 2.4 自动加载标的的可见化管理（可达性闭环）
- 现状：`auto_load_enabled` 靠"加入看板"副作用写入，无独立开关，用户不可见不可管。
- 增强方案（FR-A7）：
  - 「已缓存数据」Tab 每行增加"自动加载"开关（写 `set_auto_load_enabled`）。
  - 「自动加载」Tab 增加"当前宇宙清单"（N 个标的 + 各类型状态），支持一键移出。
- 优先级：**P1**（否则 FR-A1 的"全局规则"无人能套用到具体标的）。

### 2.5 数据查询 → 自动加载 的衔接
- 现状：取数后只能看结果，无法便捷纳入自动加载。
- 增强方案（FR-A8）：
  - 取数结果行增加"加入自动加载"按钮，一键 `set_auto_load_enabled(TRUE)`。
  - 与 FR-A7 形成"查询即订阅"的闭环。
- 优先级：**P2**。

## 3. 优先级建议（MVP 排序）

| 优先级 | 需求 | 理由 |
|---|---|---|
| **P0** | FR-A5 导出真实行情 | 名实不符，用户核心预期落空 |
| **P0** | FR-A4 自动刷新修复/下线 | 死功能伤信任，二选一必须做 |
| **P0/P1** | FR-A1~A3 自动加载可配置 | 用户明确诉求，价值最高 |
| **P1** | FR-A7 自动加载可见化管理 | 否则可配置项"套不到标的" |
| **P2** | FR-A6 复权因子增强 | 体验优化 |
| **P2** | FR-A8 查询→自动加载衔接 | 闭环体验 |

**建议 MVP 切分**：
- 第 1 批（本次重点）：FR-A1~A3（自动加载可配置，含持久化与消费改造）+ FR-A7（可见开关）。
- 第 2 批：FR-A5（导出真实行情）、FR-A4（自动刷新修复）。
- 第 3 批：FR-A6、FR-A8。

## 4. 风险与开放问题（Q）
- Q-1：复权因子/财务数据纳入自动加载后，全市场财务拉取耗时与限流风险如何评估？建议默认仅对"已手动取过财务"的标的增量补。
- Q-2：时间范围调小后，若用户后续想"回补历史"，是否需要提供显式"截断/重下历史"操作？建议本期不做，仅保留"重新规划（保留历史）"。
- Q-3：设置持久化放 DB KV 后，是否需要与 `configs/system.yaml` 的 `AUTO_LOAD_CFG` 做合并优先级约定（UI 设置 > YAML > 代码默认）？建议明确"UI 设置最高优先"。
- Q-4：自动刷新若实现，与启动时的 `init_on_startup` 盘后更新是否重复？建议统一走同一调度入口。
