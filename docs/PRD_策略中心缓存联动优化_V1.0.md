# 策略中心 × 缓存数据 联动优化分析（高级产品经理视角）

> 版本：v1.1（分析稿 + 三方评审 + 实施范围）  | 日期：2026-07-29  | 作者：产品 + 研发评审
>
> 目的：盘点当前**可缓存的数据类型**，并据此对**策略中心**提出优化建议。本文是分析 + 建议稿，不含代码改动。v1.1 增加「开发/设计/测试三方评审意见」并锁定本轮实施范围（MVP）。

---

## 0. TL;DR（结论先行）

1. **当前可缓存 5 类数据资产**：日线、分钟线、实时快照、复权因子、财务数据；由 `cache_catalog`（逐标的 × 5 类覆盖度 + 时间边界 + 自动加载开关）作为联动中枢。
2. **核心矛盾——策略中心与缓存"断连"**：策略中心现在只管"规则"（模板/参数/CRUD/导入导出），回测强依赖缓存却**不校验、不引导、不可视化**覆盖率。
3. **最该先做的 3 件事（P0）**：① 回测前"数据就绪校验" + 一键补齐；② A 股回测强制注入复权因子（否则收益口径失真）；③ 回测区间与缓存边界联动（避免越界即时取数）。
4. 体验层（P1）应让**标的选择器与缓存联动**、**策略列表显示数据就绪状态**；增长层（P2）做**可回测标的池健康度**与**策略订阅自动加载**。

## 1. 当前可缓存的数据类型盘点（事实依据）

| # | 类型 | 落库表 | 主键 / 粒度 | 市场覆盖 | 时间边界字段 | 主要回填入口 | 策略相关性 |
|---|------|--------|------------|----------|--------------|--------------|------------|
| 1 | 日线 | `bars_daily` | `(ticker, trade_date)` | A 股 + 港股通 | `daily_start` / `daily_end` | 数据中心 `fetch_bars(daily)`、`stock_zh_a_hist` | ★★★ 必选 |
| 2 | 分钟线 | `bars_minute` | `(ticker, period, bar_time)` 多周期 | A 股 only（5/15/30/60） | `minute_start` / `minute_end` + `minute_periods` | 数据中心 `fetch_bars(minute)`、`stock_zh_a_hist_min_em` | ★★ 按策略 |
| 3 | 实时快照 | `snapshots` | `(ticker, ts)` | 全市场 | `realtime_ts` | 行情看板/监控（**非**数据中心 `fetch_bars`） | ★ 弱（回测不用） |
| 4 | 复权因子 | `adj_factors` | `(ticker, trade_date, adj_type)` | A 股 only（qfq/hfq） | 由日线区间推导 | 数据中心 `fetch_bars(adj)`（三序列收盘价推导） | ★★★ A 股收益口径 |
| 5 | 财务数据 | `financials` | `(ticker, report_date, indicator)` | 主要 A 股 | `fin_report_end` | 数据中心 `fetch_bars(financials)`、`stock_financial_abstract` 宽表 | ★★ 基本面策略 |

**联动中枢**：`cache_catalog` 逐标的记录 `has_daily / has_minute / has_realtime / has_adj / has_financials` 五类布尔覆盖度、各自时间边界、以及 `auto_load_enabled` 自动加载开关。`v_cache_summary` 视图聚合每类行数，供缓存目录页与看板健康度共用。

**关键产品事实（来自代码）**：
- 分钟线为**多周期**，落库主键含 `period`，不同周期独立存储、互不覆盖。
- 复权因子仅 A 股；港股无复权口径，取数直接失败。
- 财务为**宽表转置**后的 `(report_date, indicator, value)` 长表，便于按指标检索。
- 实时快照的写入在监控/看板链路，不由数据中心 `fetch_bars` 驱动——它是"快照"而非"历史序列"，对回测无意义，但可作为策略实时信号的潜在数据源（未来可行性）。

## 2. 现状评估：策略中心与缓存的关系

**策略中心现在做什么**（`strategy_center.py` + `strategy_service.py`）：
- 6 类模板（SMA/MACD/Bollinger/RSI/Buy&Hold/自定义 DSL）的新建向导（向导**只配参数**，如快慢线周期）。
- 策略 CRUD、导入/导出（JSON）、启停开关。
- `StrategyConfig` 含 `symbols: list[str]`（标的池）与 `params`，但**无回测起止日期、无数据类型范围、无缓存关联字段**。

**回测链路**（`backtest/engine.py`）：`BacktestEngine` 接收预加载的 `bars_df`，按 `TimePlayer` 逐根 bar 驱动策略。**数据从哪来**由调用方决定——若调用方从缓存读 `bars_daily`/`bars_minute` 则快且离线；若缺失则只能网络取数（慢、受限流、易失败）。

**断连点（PM 视角的痛点）**：
1. **不选标的是否已缓存**：`symbols` 自由填，中心不校验其是否在 `cache_catalog`、是否 `has_daily` 覆盖回测区间。
2. **不绑定回测区间到缓存边界**：无"使用缓存区间"快捷项，用户易填出越界区间 → 触发即时取数或空结果。
3. **不感知复权**：A 股回测若未应用 `adj_factors`，前/后复权价格未归一，收益率口径错误（这是量化回测的 correctness 红线）。
4. **不感知财务**：用基本面指标的策略，无 `has_financials` 校验，回测时指标缺失静默失效。
5. **无"数据就绪体检"**：点击回测时，中心无法提前告知"此策略 12 只标的中 3 只缺日线、2 只缺复权"，只能事后报错。
6. **分钟线策略盲区**：用分钟线的策略，中心未提示"仅 A 股、需指定 period、需 `bars_minute` 已缓存"。

## 3. 优化建议（按优先级）

### P0 — 正确性与阻断（必须做）
- **P0-1 回测前"数据就绪校验"**：基于 `cache_catalog` 校验 `策略.symbols × 回测区间 × 所需类型`。规则：日线必选；分钟线策略须 `has_minute` 且 `period` 命中；A 股须 `has_adj`；基本面策略须 `has_financials`。缺失则**阻断回测**并给出"缺失清单 + 一键补齐到缓存"按钮。
- **P0-2 复权因子强制注入**：A 股回测必须按所选 `adj_type`（默认 qfq，可选 hfq）应用 `adj_factors` 归一价格；中心在向导增加"复权口径"选择，并在回测记录中留痕。
- **P0-3 回测区间与缓存边界联动**：向导提供"使用缓存区间（`daily_start`~`daily_end`）"快捷选项，并高亮"超出缓存边界将即时取数"的警告。

### P1 — 体验与效率（应做）
- **P1-1 标的选择器与缓存联动**：标的选择下拉 = 已缓存标的优先，每项带覆盖度徽章（日/分/复/财 5 类打勾），未缓存标的灰显并标注"未缓存"。
- **P1-2 策略列表"数据就绪"状态**：策略表新增列，显示 ✓ 可回测 / ⚠ 缺数据（及缺哪类），点击定位缺失项。
- **P1-3 一键补齐**：对缺失标的/类型触发数据中心 `fetch_bars` 回填，进度可见、可取消，回填完自动刷新就绪状态。
- **P1-4 财务因子可用性提示**：若策略 DSL/参数引用财务指标，校验 `has_financials` 并提示具体缺哪些 `indicator`。

### P2 — 智能与增长（可做）
- **P2-1 可回测标的池健康度面板**：策略中心首页展示"已就绪可回测标的数 / 总缓存标的""覆盖度分布""近 7 日未刷新标的"，呼应 `v_cache_summary`。
- **P2-2 策略订阅自动加载**：策略可被"订阅"到自动加载任务（`auto_load_enabled`），保证其 `symbols` 每日增量刷新，回测永远有新鲜数据。
- **P2-3 分钟线策略引导**：用分钟线的策略，向导提示限制（仅 A 股、需 period）并自动预检 `bars_minute` 覆盖。
- **P2-4 数据血缘 / 可复现**：回测记录关联数据指纹（区间、复权口径、bars 行数、快照时间），与既有 `repro.compute_input_hash` 对齐，保证结果可复现、可审计。

## 4. 验收标准（建议）
- **AC-1** 点回测时，若 `symbols` 中任一标的在回测区间内缺 `has_daily`，阻断并展示缺失清单。
- **AC-2** A 股策略回测记录中可查"复权口径"字段，且价格序列确为复权归一后。
- **AC-3** 标的选择器对未缓存标的显示"未缓存"徽章，点击可一键补齐并实时刷新。
- **AC-4** 策略列表"数据就绪"列与 `cache_catalog` 实时一致。
- **AC-5** 选"使用缓存区间"后，回测不触发任何网络取数（离线可跑）。
- **AC-6** 订阅自动加载的策略，其 `symbols` 在每日增量刷新后 `last_update` 更新且就绪状态翻转。

## 5. 风险与依赖
- **依赖**：P0-1/P1-3 依赖数据中心 `fetch_bars` 与 `cache_catalog` 查询接口稳定（现状已具备）。
- **风险**：一键补齐可能触发 akshare 限流（数据中心已有保守模式/限速，须复用，避免把补齐变成限流雪崩）。
- **边界**：实时快照 `snapshots` 对回测无意义，本期不纳入策略数据就绪校验；仅作为未来"实时信号"可行性预留。

## 7. 三方评审意见（v1.1 新增）

### 7.1 开发（Dev）视角
- **D1【中】缺失"阻断 vs 提示"策略定义**：原 P0-1 写"阻断回测"，但未区分「全缺（无可跑）」与「部分缺（其余标的仍可跑）」。直接硬阻断会让"全部缓存标的"默认路径之外的场景体验陡降。→ 改进：仅当**所选范围内无任何标的具备所需数据**时硬阻断；部分缺失时**仍跑可用标的**并在结果区给出缺失清单（不静默跳过）。
- **D2【中】复权注入口径需确定且留痕**：原 P0-2 说"默认 qfq，可选 hfq"，但回测 UI 当前无复权选择器，直接硬编码 qfq 会掩盖口径选择。→ 改进：本轮回先在后端对 A 股默认应用 qfq（收益口径正确），并在回测结果记录中落地"复权口径"字段（AC-2 可追溯）；后续迭代再加 UI 选择器。
- **D3【低】就绪校验依赖 `cache_catalog` 覆盖度，非物理表行数**：覆盖度由取数流程维护（`has_*` 布尔），与 `bars_daily` 实际行数可能短暂不一致（取数中途失败）。→ 改进：校验时**同时核对 `cache_catalog.has_*` 与日期边界**（`daily_start/end`），边界不符即判为不可就绪；物理表空但 `has_daily=TRUE` 的极端情形由既有自愈覆盖。
- **D4【低】"使用缓存区间"需对齐多标的并集边界**：不同标的 `daily_start/end` 不同，应取**所有标的的并集**（min start ~ max end），避免单标的边界把区间缩太窄。
- **D5【中】金融因子校验要可判定**：P1-4 的"DSL 引用财务指标"需明确判定规则，否则易误报。→ 改进：仅当 `type==custom` 且 DSL 文本含 `financials`/`财报`/`财务指标` 关键字时，才把 `financials` 列为必需；其余策略不强制。

### 7.2 设计（Design）视角
- **S1【低】"数据就绪"状态需三态而非二态**：✓可回测 / ⚠部分缺（仍可跑）/ ✗全缺（不可跑），避免把"部分缺"误显示成红叉造成误判。
- **S2【低】缺失清单信息密度**：清单应呈现「标的 + 缺哪类（日/复/财）+ 是否越界」，一行一条、可点击定位；避免大段文本。
- **S3【低】向导内嵌比弹窗更顺**：P0-3 的"使用缓存区间"与越界警告放在**向导步骤 3（标的池）同页**比独立弹窗更连贯；覆盖度徽章紧贴标的下拉。
- **S4【低】术语统一**：全文"复权因子 / adj / 前复权"统一为"复权口径（前复权 qfq / 后复权 hfq）"，降低用户认知成本。

### 7.3 测试（Test）视角
- **T1【中】后端服务必须单测全覆盖**：`required_types_for` / `check_data_readiness` / `load_adjusted_bars` / `cache_range_for` 四个纯函数（依赖 `cache_catalog` 查询）须有单测，用 monkeypatch 注入 catalog 行，断言：A 股触发 adj 必需、越界判定、复权价格 = raw/factor、并集边界。
- **T2【中】回测拦截单测**：构造"标的缺日线"与"越界"两类场景，断言 `run_backtest` 返回就绪清单而非静默空结果（AC-1/AC-5）。
- **T3【低】列表就绪列单测**：`_build_strategy_list` 注入 readiness 后，断言列渲染三态文案正确。
- **T4【低】不破坏既有回测**：默认"全部缓存标的"路径须仍通过现有回测集成测试（就绪校验对缓存标的为 pass）。

## 8. 本轮实施范围（MVP，v1.1 锁定）
依据评审收敛为可独立交付、可测的 MVP，避免一次性大改引入回归：

| 项 | 对应 | 范围 | 是否本轮 |
|---|------|------|----------|
| 数据就绪校验后端 | P0-1/D1/D3/D5 | `strategy_data_service`：必需类型推导 + 就绪报告（含越界）+ 拦截逻辑 | ✅ |
| 复权因子注入 | P0-2/D2 | 后端对 A 股默认 qfq；回测结果记录复权口径 | ✅ |
| 缓存区间联动 | P0-3/D4/S3 | 向导步骤3"使用缓存区间"按钮 + 越界警告 | ✅ |
| 策略列表就绪列 | P1-2/S1 | 三态（✓/⚠/✗）+ 悬停缺失清单 | ✅ |
| 标的覆盖度徽章 | P1-1/S3 | 向导标的下拉每项显示 日/复/财 覆盖勾 | ✅ |
| 财务因子提示 | P1-4/D5 | custom DSL 含财务关键字时校验 `has_financials` | ✅ |
| 一键补齐 | P1-3 | 复用 `fetch_bars` 回填 + 进度；UI 较重 | ⏸ 下期 |
| 健康度面板 / 订阅自动加载 | P2-* | 增长项 | ⏸ 下期 |

### 修订后验收标准（替换 §4）
- **AC-1** 回测所选范围内**任一标的在区间内缺必需类型（日线必选；A 股须 adj；财务策略须 financials）** 时，返回就绪清单并（全缺时）阻断，绝不静默空跑。
- **AC-2** A 股回测结果记录含"复权口径=qfq"字段，且价格序列为 `close/adj_factor` 复权归一后。
- **AC-3** 向导标的下拉对未缓存标的显示"未缓存"且可一键"使用缓存区间"对齐边界；覆盖度以 日/复/财 勾选呈现。
- **AC-4** 策略列表"数据就绪"列三态（✓可回测 / ⚠部分缺 / ✗全缺）与 `cache_catalog` 实时一致。
- **AC-5** 点"使用缓存区间"后，回测区间 = 各标的 `daily_start/end` 并集，不触发越界即时取数。
- **AC-6** custom DSL 引用财务指标而标的 `has_financials=FALSE` 时，就绪清单标记该标的缺"财务"。
- **AC-7（测试）** `strategy_data_service` 四函数单测 + 回测拦截单测 + 列表就绪列单测全绿。
